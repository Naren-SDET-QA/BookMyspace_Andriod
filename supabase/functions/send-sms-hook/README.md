# BookMySpace WhatsApp OTP

The existing Supabase Auth Send SMS Hook is used as the OTP delivery hook, but delivery is routed to WhatsApp instead of an SMS provider.

Supabase Auth generates and verifies the OTP. The hook only transports the generated OTP to the user's WhatsApp number. This means the existing registration, phone verification, sign-in OTP and password/recovery flows keep using Supabase Auth's verification logic.

Supabase documents the Send SMS Hook specifically as a way to use alternate messaging channels such as WhatsApp. citeturn0search0

## Required secrets

Configure these in the Supabase Edge Function environment:

- SEND_SMS_HOOK_SECRET — generated by the Supabase Auth Hooks configuration.
- WHATSAPP_SERVICE_URL — private HTTPS URL of the BookMySpace Baileys service.
- WHATSAPP_API_KEY — the same secret configured on the WhatsApp service.

Never put WHATSAPP_API_KEY in Flutter, Web, Android, iOS, or the repository.

## Behavior

1. Supabase Auth generates the OTP.
2. Supabase Auth calls `send-sms-hook`.
3. The hook verifies the Standard Webhooks signature.
4. The hook sends the OTP to the user's WhatsApp number.
5. Supabase Auth continues to verify the OTP normally.
6. If WhatsApp delivery fails, the hook returns an error instead of silently sending an SMS. This keeps the configured policy WhatsApp-only.

## Deploy

```bash
supabase functions deploy send-sms-hook
supabase secrets set WHATSAPP_SERVICE_URL=https://your-private-whatsapp-host.example
supabase secrets set WHATSAPP_API_KEY=your-long-random-secret
```

Then configure Supabase Dashboard → Authentication → Hooks → Send SMS Hook to point at the deployed function and use its generated webhook secret.

## Important

The WhatsApp number used by BookMySpace must be paired with the Baileys service and its authentication state must be stored on persistent server storage.

Do not use this integration for unsolicited bulk messaging.
